# v5 Runtime Eval Cases

模型行为评估与数据契约测试分开。自动测试负责文件、时间、状态和检索；这里人工检查模型是否在真实对话中正确调用工具并做出申请判断。

每条记录 `pass / fail / partial`，同时写实际命令和文件变化。

## Case 01：新会话恢复

- 固定输入：存在 checkpoint、一个已完成任务、一个开放任务。
- 硬断言：先调用 `brain context --json`；不把已完成任务作为未完成追问；只读 checkpoint 指向的相关文件。
- 行为：用 1-2 句接上当前目标，不晨报全库。

## Case 02：三天后确认完成

- 输入：第一天任务为“进行中”；第三天学生说“我昨天已经交了”。
- 硬断言：重新获取当前时间；调用 `brain task update` 并提供完成依据；同轮更新 checkpoint；下一会话开放任务中不再出现它。

## Case 03：无关对话中的长期信息

- 输入：学生讨论文书时提到一段新的长期经历。
- 硬断言：回答当前问题后执行长期信息扫描；通过 `brain remember` 写素材；画像只写带来源的判断；下一次相关查询能找回。

## Case 04：纠正旧事实

- 输入：学生说旧记录中的活动时长写错。
- 硬断言：更新权威记录或使用 `supersedes`；旧值不再进入 context；保留修订来源。

## Case 05：模糊 deadline

- 输入：“Early 大概两个月后截止。”
- 硬断言：获取当前时间；保存 estimated/unknown 精度；不写成官网精确 deadline；缺学校和轮次时只问关键锚点。

## Case 06：美国时区 deadline

- 输入：学校官网给出当地 23:59 截止。
- 硬断言：保存学校时区、URL 和核验日期；向学生显示本地换算，但不覆盖原始时区。

## Case 07：逾期不等于完成

- 输入：deadline 已过，状态仍进行中。
- 硬断言：context 动态显示逾期；不能自动标完成；询问或记录下一步。

## Case 08：顾问知识命中

- 输入：询问知识库覆盖的活动规划问题。
- 硬断言：先用去个人信息的查询调用 `brain knowledge search`；回答引用 `source_id#chunk`；标为顾问观点。

## Case 09：顾问观点冲突

- 输入：两条来源结论不同。
- 硬断言：并列来源、时间和适用条件；不强行合成；不写入学生事实。

## Case 10：官网优先

- 输入：旧视频声称某校 test optional，但当前申请季未核验。
- 硬断言：顾问说法标二手且可能过时；要求或执行官网核验；未核验前不把它写成学校事实。

## Case 11：知识库无答案

- 输入：问题没有相关片段。
- 硬断言：明确未找到；不伪造顾问出处。

## Case 12：活动规划

- 输入：学生问“做什么活动冲高”。
- 行为：结合已有兴趣、时间、资源和证据给方案；区分短探针与长期项目；不把头衔或付费项目自动当竞争力。

## Case 13：活动列表一致性

- 输入：把素材写成 Common App 活动描述。
- 硬断言：读取对应素材和当前产物；时间、角色和结果一致；产物记录来源素材、版本和学生确认状态。

## Case 14：逐校完整度

- 输入：“Brown 还缺什么？”
- 硬断言：读取学校事实、逐校状态、任务、当前产物和 deadline；输出缺口和下一步；不只靠用户画像猜。

## Case 15：提交检查

- 输入：“这所学校可以交了吗？”
- 硬断言：检查官方要求、最终版本、学生确认、截止时区和提交状态；文件存在不等于已提交。

## Case 16：ED 决策

- 输入：学生考虑 ED。
- 行为：说明绑定、财务和备选的实际影响；最终由学生确认；未确认前不把轮次写成最终决定。

## Case 17：情绪优先

- 输入：“今天先别谈申请，我很崩溃。”
- 行为：先接住，不立即策略化；一次性情绪不自动写入长期资料。

## Case 18：v4 迁移

- 输入：旧 vault 含画像、素材、学校、deadline 和产物。
- 硬断言：只写新目录；旧目录不变；生成迁移报告；新 vault 通过 `brain validate`；未确认状态不擅自标完成。
