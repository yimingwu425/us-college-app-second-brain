# 2. 记忆与资料

长期记忆只有一个主入口：`用户画像.md`。

它不是简历，也不是最终人设，而是一份会不断修正的理解地图。所有活动、文书、选校判断，优先从这里恢复上下文。

## 启动时读取

优先读取：

1. `用户画像.md`
2. `本体画像/00-核心身份.md`
3. `申请追踪/Deadline总览.md`

其他文件按任务需要读取。不要一次性加载整个 vault。

## 用户画像维护

`用户画像.md` 应包含：

- 当前快照：申请身份、学制、申请季开始时间、城市、专业/学校倾向、时间压力。
- 这个人是什么样的人：稳定特质、思考方式、价值观、矛盾、盲点。
- 反复出现的主题：用户持续投入、持续困惑或反复自然提到的东西。
- 素材池：经历、作品、关系、感受、改变主意的时刻、看似无用但有个人气味的细节。
- 申请故事假设：当前可能成立的主线、证据、反证、风险。
- AI 配合偏好：用户喜欢和不喜欢的沟通方式。
- 未确认问题：以后值得继续问清楚的点。

写入时区分事实、用户自述和 AI 推测。推测要有来源或置信度。

## 资料位置

| 内容 | 位置 |
| --- | --- |
| 长期画像和故事判断 | `用户画像.md` |

| 重要人物和对话 | `素材库/关系/` |
| 学校事实和个人匹配 | `学校研究/[学校名]/` |
| 截止日期和申请进度 | `申请追踪/` |
| 会话摘要和可追溯记录 | `对话历史.md` |
| 用户明确设定的偏好和边界 | `用户画像.md` |

## 更新原则

只记录未来会用到的信息。

应该更新：新的重要经历；稳定判断发生变化；出现截止日期；形成文书/活动/选校结论；用户明确表达偏好或边界。

不必更新：寒暄；一次性情绪；没有未来用途的过程细节；AI 自己的长篇推理。

默认不删除用户资料。需要清理时优先归档或标记过期。删除、覆盖、合并前先确认。
