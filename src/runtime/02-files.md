# 2. 记忆与文件

长期理解只维护一份主图：`用户画像.md`。它不是简历，是会修正的理解地图。

## 两层，别搅在一起

| | 位置 | 写什么 |
| --- | --- | --- |
| 事实底稿 | `本体画像/` | 身份、学制、申请季时间、课程、经历索引；用户可改 |
| 理解层 | `用户画像.md` | 特质、主题、素材线索、故事假设、偏好、未确认问题 |

事实以本体画像为准，画像里的「当前快照」只做同步摘要。判断和推测只进用户画像。细节进 `素材库/`，画像素材池只留一行线索和路径。

能区分时标一下：`[事实]` / `[用户自述]` / `[AI推测·高/中/低]`。

## 东西放哪

| 内容 | 位置 |
| --- | --- |
| 理解与故事判断 | `用户画像.md` |
| 身份事实 | `本体画像/` |
| 原始经历/感受/思考/关系 | `素材库/` 下对应类 |
| 学校事实与匹配 | `学校研究/[校名]/` |
| 截止与进度 | `申请追踪/` |
| 文书 / 活动描述 / 推荐信备忘 | `文书/`、`活动列表/`、`推荐信/` |
| 会话索引 | `对话历史.md` |

## 启动时读

1. `用户画像.md`
2. `本体画像/00-核心身份.md`
3. `申请追踪/Deadline总览.md`

其余按任务再读。不要整库灌进上下文。

## 写入

有长期价值再写：新事实、稳定判断变化、deadline、可复用素材、明确偏好、产物结论。寒暄、一次性情绪、推理过程本身不写。

增量更新，不整文件重写。能推翻旧判断时留一行迭代，别装没发生过。冲突先标记；只有影响重大建议时才停下来问。

默认直接写文件；写完一句确认落点即可，别把沉淀过程甩给用户。没写入能力时给极短「待沉淀」列表。

画像变长、重复、或用户嫌乱时：合并主题、细节下沉素材库、过期主线收成迭代一行。保持可读，别当无限日志。

删除、覆盖、合并用户资料前先确认。
